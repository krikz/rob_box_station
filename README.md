# rob_box_station — хост РОББОКСа на Яндекс Станции Лайт

Колонка без Алисы, на которой крутится ядро диалога РОББОКСа (`rob-box-dialog-core`): микрофон → VAD → STT → ход v2 →
TTS → динамик. Границы и план — ADR-0167 в `krikz/rob_box_project` (`docs/adr/0167-dialog-core-repo-and-station-repo.md`).

## Установка одной строкой

С компьютера (Linux, Mac, Git Bash), где есть SSH к колонке после рута
([runbook](https://github.com/krikz/rob_box_project/blob/develop/docs/runbooks/yandex-station-root.md)):

```bash
curl -sL https://raw.githubusercontent.com/krikz/rob_box_station/main/install.sh | sh -s -- 10.1.1.13
```

Ставит три ассета релиза — то, чего на колонке ещё нет (`FORCE_RUNTIME=1` / `FORCE_CORE=1` / `FORCE_KWS=1` —
переставить), — потом код колонки последнего **тега**, автозапуск, глушение Алисы, приветствие SSH. Дальше — ключи на
странице `http://<колонка>:8080`. Обновления — «Игорёк, проверь обновление» / «Игорёк, обновись». `DRY_RUN=1` — шаги
без изменений.

| Ассет | Что | Сборка (детерминированная) |
|---|---|---|
| `station-runtime-armv7.tar.gz` | Питон 3.12.16 armv7 + библиотеки → `/data/opt/python`, `rbx/site` | `tools/build_runtime.py` по `tools/runtime.lock` (URL + sha256) |
| `station-core.tar.gz` | ядро диалога → `rbx/core` (`.env` переносится) | `tools/build_core.py` из коммита `tools/core_ref.txt` `rob_box_project` |
| `station-kws-armv7.tar.gz` | своя модель вейка → `rbx/kws` (необязательна) | `kws_run.c` → `build_kws.sh`, веса `training/kws/models/` |

Собирает их CI (`.github/workflows/assets.yml`) на каждый тег `v*` и прикладывает к релизу с `SHA256SUMS`; руками —
Actions → assets → Run workflow. Сверено 09.11 с колонкой 10.1.1.13: рунтайм — 2435 из 2435 бинарников и файлов
библиотек байт в байт, `kws_run` — тот же md5; ядро на колонке было снимком Windows-чекаута (CRLF, файлы разных
коммитов), поэтому закреплено ядро `develop` `e3e57efb` — хост на нём проверен ходами (время, поиск, тул жалобы).
Ассет ищется под тегом, затем в любом релизе; свой адрес — `RUNTIME_URL` / `CORE_URL` / `KWS_URL`. Место считается
по тому, чего нет: всё с нуля — 67 МБ на `/data` (`NEED_MB=NN` — переопределить).

## Жалоба в GitHub («Игорёк, пожалуйся»)

Голосом: «Игорёк, пожалуйся, что не слышишь меня» — колонка заводит issue в `krikz/rob_box_station`
(`RBX_REPORT_REPO` меняет репозиторий). Фразу разбирает код (`station_report.report_command`), тело issue собирает
`station_report.Reporter`: дословная жалоба, `VERSION`, настройки без ключей и значимые строки `/tmp/station.log`
(и `.1`). «Пожалуйся без лога» — без строк лога; значения ключей маскируются (`mask_secrets`).

Нужен отдельный токен `GH_ISSUE_TOKEN` на странице `:8080` — fine-grained, право **Issues: Read and write** только
на `krikz/rob_box_station`. Пауза между жалобами — 10 минут (`RBX_REPORT_COOLDOWN_S`); та же жалоба в это окно
второй раз не уходит.

Поля токена обновлений (`GITHUB_TOKEN`) на странице **нет намеренно** (08.11): обновлениям токен не нужен —
репозиторий публичный, — а лишнее поле сбивало: отозванный токен из него давал `401`, и колонка говорила «не смог
проверить обновление». Сейчас негодный токен в `.env` обновлениям не мешает: чтение повторяется анонимно. Если
репозиторий когда-нибудь закроют, `GITHUB_TOKEN` вписывается в `.env` руками.

Оформление issue делает модель (DeepSeek ключом колонки): получает ФАКТЫ и правила `ISSUE_PROMPT`, возвращает строгий
JSON `{title, body}`. Код проверяет ответ — жалоба в теле дословно, все числа только из фактов, заголовок по правилам;
не прошло (или модели нет) — issue оформляется шаблоном кодом, жалоба не теряется.

## Хендофф 09.11 (начинать отсюда)

Залито на `10.1.1.13` руками поверх v0.1.13 (старые файлы — `/data/opt/rbx/prev_manual/`), в тег ещё не вошло.

* **STT: MiniMax → Яндекс** (`scripts/station_stt.py`, #4550 в `rob_box_project`). REST v1 SpeechKit на urllib, ключи
  `YANDEX_API_KEY` + `YANDEX_FOLDER_ID` (оба на странице). 429/сеть/ошибка — сразу Яндекс; MiniMax молчит дольше
  `RBX_STT_HEDGE_S` (2 с) — Яндекс параллельно. Своя модель слышит имя (`igorek` ≥ `RBX_KWS_EARLY_P` 0,6) или идёт окно
  без вейка — Яндекс сразу наперегонки: замер 09.11 на записях колонки — Яндекс 0,47–0,57 с, MiniMax 1,29–2,43 с.
  На весь фон Яндекс не зовётся — он платный за запрос. Порядок — `RBX_STT_ORDER` (`minimax,yandex`).
* **Отзывчивость** (`serve`): кольцо «думаю» через 0,4 с по своей модели, а не через 2–3 с облака; сбой STT/хода/сети,
  когда звали колонку, — красное кольцо и фраза, что сломалось («нет интернета», «распознавание не отвечает», «модель не
  отвечает»), а не тишина; ход под таймаутом `RBX_TURN_TIMEOUT_S` (45 с) и `try`; при старте «Игорёк на связи» или
  «Обновился до версии …» (#15); микрофон кнопкой — голосом; после голого «Игорёк» и «Слушаю.» следующая фраза без
  имени идёт колонке **с командами кода** (#13: «проверь обновления» уходило модели).
* **Офлайн-фразы** (`scripts/station_offline.py`): синтез заранее тем же голосом в `/data/opt/rbx/offline/`
  (11 фраз, 1,3 МБ, 23 с), пересинтез при смене голоса; синтез упал — запасная фраза или тон кодом.
* **Вейк** (`scripts/station_kws.py`): сбор стоял с 08.11 09:37 — общий кап 10 МБ съели «чужие» (264 против 14).
  Теперь у `pos`/`neg`/`miss` свои потолки и запас 8 МБ на диске; `miss` — попытки позвать перед удачной (15 с) и пустой
  STT при «Игорьке» своей модели, лог `🔑 вейк с N-й попытки`; `index.jsonl` — текст STT и ответ модели к каждому файлу.
  «Чужое» пишется только если следом не звали. Вейк по созвучию: «Горек», «и горек» (1 правка), «Игорь» — только если
  своя модель слышит имя. `pull_real.sh` забирает и `miss` (в обучение не идёт — сначала разметить).
* **Жалобы**: тул модели `report_issue` (хост дописывает его в каталог ядра при старте, класс `query`, виден всегда) —
  модель даёт жалобу, заголовок и суть, тело собирает код без второго вызова LLM; проверено ходом с `RBX_REPORT_DRY=1`.
  Код по-прежнему ловит фразу первым: добавлены «передай разработчикам» (#16 уходило модели) и «жалуюсь»; разные жалобы —
  через 45 с, а не 10 мин. Факты устройства говорят модели, что жаловаться она может, и какие фразы решает код.
* **Страница**: `/log` — значимые строки лога, свежее сверху, ключи скрыты (#17); поле `YANDEX_FOLDER_ID`.
* **install.sh**: Алиса глушится в переднем плане с проверкой `ps` (#4551).

Своя модель на `10.1.1.13` по-прежнему слабая для решения вейка (09.11 «Игорёк, ты здесь?» → `_unknown_ 0.99`; голос
колонки из динамика → `igorek 0.98`) — поэтому `RBX_KWS_DECIDE` не включён; сначала `pull_real.sh` и переобучение на `miss`.

## Хендофф 07.11 вечер

**Работает на колонке** (v0.1.4 + заливки до `7197a4f`): промпт колонки «Игорёк» (`prompts/`), честные инструменты (музыка, лицо,
звуки — «на колонке нет»; громкость — `amixer`; адрес, сеть, страница — факты устройства в промпт), поиск в интернете
(DeepSeek), кнопки и кольцо (анимации Алисы), страница `:8080` (вейк, голос, громкость, промпт, Wi-Fi, ключи), Wi-Fi по Bluetooth
(Improv, проверено с телефона), Bluetooth-музыка с телефона и пульт голосом (трек с телефона не проверен), самообновление
по тегам (проверено вживую v0.1.0 → v0.1.4), своя модель вейка v2 в **режиме тени** (`training/kws`, лог `🔑 kws`).

**Ждёт «да» Шифу в чате приложения:** ассет `station-runtime-armv7.tar.gz`, приложенный к тегу (без него `install.sh` не
ставит Питон); строка приветствия SSH в `/etc/profile.d/rbx.sh` (сам `motd.sh` уже в v0.1.5); перенос ключа Яндекса с робота.

**Дальше по порядку:** вейк своей моделью вместо облака (порог 0,8) → стоп/громче/тише без облака → распознавание Яндексом →
больше голосов в обучении и модель для робота → напоминания и будильник → устройства через MCP-плагины (лампа
[mylamp](https://github.com/GOODWORKRINKZ/mylamp) на Lux, пылесос STYTJ01ZHM по miIO, школьный дневник) → звонки (`hfp-hf`) →
вынос ядра (ADR-0167 Ш1–Ш2).

6. ADR-0167 Ш1 в `rob_box_project` (промпт, `wake_words.yaml`, `migrations/*.sql` — в пакет ядра), затем Ш2 — залить
